# ⌚ Xiaomi Watch Self-Host Monitor

### Watch your own servers' status from the screen of a Xiaomi (HyperOS) watch

[English](README.md) · [Türkçe](README.tr.md)

HyperOS is a closed system — third-party apps normally can't be installed on the
watch. This repo shows the **end-to-end** path to run your own **Vela quick-app**
on the watch and give it internet access through the **AstroBox bridge**. The
example app, **Nabız** ("pulse" in Turkish), polls your servers' `/health`
endpoints, shows their status in color, and vibrates your wrist when a service
goes down.

## ✨ Features

- **Real health checks** — not just "does the site load"; it reads the JSON at
  your `/health` endpoint. Two schemas are auto-detected:
  - `{"ready":true,"database":true,"relay_server":true,...}` (component-based)
  - `{"status":"ok","version":"...","time":"..."}` (status + version + freshness)
- **Vibration alert** — wrist buzzes when a service goes down (4 pulses), and
  when it recovers (2 pulses). Only on state *change*; no spam.
- **False-alarm guard** — marks "down" only after N consecutive failures, not one.
- **Freshness check** — if the `time` field is stale, shows "suspicious"
  (possible cached response).
- **N services** — monitors as many services as you list in `config.js`.
- **Tap to refresh instantly**, auto-refreshes every 30 s.
- **Fully local** — data flows only between your watch ↔ phone ↔ your server.

## 🧩 How it works

```
┌──────────────┐    BLE/SPP     ┌───────────────┐    internet    ┌─────────────┐
│ Xiaomi Watch │ ─────────────> │     Phone     │ ─────────────> │ Your server │
│ (Nabız app)  │    AstroBox    │  FetchBridge  │                │   /health   │
│   fetch()    │ <───────────── │   (bridge)    │ <───────────── │             │
└──────────────┘                └───────────────┘                └─────────────┘
```

HyperOS watches can't reach the internet directly (Wi-Fi isn't exposed to
quick-apps), so all traffic goes through the phone bridge. AstroBox's
**FetchBridge** plugin sets up this bridge; the watch's `system.fetch` call
uses the phone's internet.

## 🚀 Setup (summary)

See **[guide/](guide/)** for full steps. In short:

1. Install **AstroBox** ([astrobox.online](https://astrobox.online)) and connect
   the watch (an auth key is required — the guide explains how to obtain it).
2. Install the **FetchBridge** plugin from AstroBox and set it to "listen" for
   your app.
3. Build this repo:
   ```bash
   cd app
   cp src/config.example.js src/config.js   # write your own services
   python3 tools-make-logo.py                # generate the logo
   npm install && npm run build              # produces the .rpk
   ```
4. Install the produced `.rpk` onto the watch via AstroBox (or Gadgetbridge).

## ⚙️ Configuration

`app/src/config.js` (copied from the example; not committed):

```js
export var SERVICES = [
  { name: 'Service A', url: 'https://example.com/health/ready' },
  { name: 'Service B', url: 'https://api.example.org/health' }
]
export var INTERVAL_MS = 30000     // check interval
export var FAIL_THRESHOLD = 2      // failures before "down"
```

Your health endpoint only needs to return `200 + JSON`. For a sample (nginx)
endpoint, see [guide/health-endpoint.md](guide/health-endpoint.md).
